# Monitoring integrity boundary

## Decision

Mandatory protection is a hybrid.

Python instrumentation stays for semantic decisions: which asset, which
invariant, which approval, which predictive path. It is tier `INTERCEPTED`.
Coverage status for that tier is `PARTIAL`. It is not `ENFORCED` and it is not
`VERIFIED`.

The mandatory restriction is applied by the operating system before the agent
runs:

- Darwin, tested on this host: a deny-by-default Seatbelt profile
  (`sandbox-exec`) generated by `varden.monitoring_integrity.boundary`. The
  supervisor launches the agent. Children inherit the profile. The protected
  directory is not on the write allow list. The approval secret is excluded
  from the read allow list with `require-not`. Signals to other processes are
  not allowed. Outbound TCP is denied except an explicit gateway port.
- Linux, reference only: `varden-agent` and `varden-watch` are different
  users. Protected files are `root:varden-watch` mode `0640`. The agent is not
  in that group. See `deploy/monitoring-integrity/linux/`. This was not
  executed here. Docker is installed on the development host and the daemon
  was not running. The script refuses to run without root and `--apply`.

`VERIFIED` is produced only by `run_gauntlet` after the attacks below leave
the protected bytes unchanged, the positive controls succeed, and the
uncontained concatenation control does change its own file. `posture()` does
not run that probe and does not report `VERIFIED`.

## Rejected alternatives

An external broker that the agent can still bypass was rejected. If the agent
user can `open()` the monitoring file, a broker on the side is not a boundary.
More monkeypatches were rejected for the same reason: `os.execv`, ctypes, a
saved `open`, and a concatenated shell path already bypass them. That
concatenation remains a passing regression test for the interceptor
(`test_concatenated_shell_path_is_a_known_unobservable_bypass`).

A blanket `(allow default)` plus a later deny was rejected. On this kernel the
deny does not win, and the write succeeds. The profile is deny-by-default.

## Trust boundary

| Component | Authority |
| --- | --- |
| Supervisor | Writes the profile, owns the approval secret, launches the agent, runs the probe |
| Agent process tree | Seatbelt or the `varden-agent` uid. Cannot write protected files, read the secret, or signal the watchdog |
| Watchdog | `varden-watch` on Linux. On Darwin, any process not launched under the profile. A missed heartbeat is not sabotage |
| Remote MCP server | Not covered by the local profile. Direct TCP from the agent is denied unless the port is the gateway allowlist. The server's own files are `NOT_ENFORCEABLE` |

An unsandboxed process of the same macOS user can still write the file. The
guarantee is the launched tree, not the user. Linux user separation would
cover every process of that uid. That stronger claim is not marked tested.

## Protection tiers

| Tier | Meaning | Coverage status |
| --- | --- | --- |
| `OBSERVED` | Visible, not necessarily preventable | `OBSERVATIONAL` |
| `INTERCEPTED` | A patched call can be blocked. Equivalent-authority code can bypass it | `PARTIAL` |
| `BOUNDARY_ENFORCED` | The OS profile or inode check denied the operation | `PARTIAL` until a probe verifies the deployment |
| `VERIFIED` | A fresh probe showed the denial, unchanged bytes, a live watchdog, an unreadable secret, and working legitimate writes | Still not a claim about unsandboxed or remote code |
| `UNKNOWN` | Evidence missing, stale, or mismatched | `UNCOVERED` |
| `NOT_ENFORCEABLE` | No applicable boundary. The concatenation control and remote MCP files use this | `NOT_ROUTED` |

`coverage ENFORCED` remains the existing interceptor probe. MIP does not use
it to mean the OS boundary.

## Reproduce the Darwin probe

```bash
varden runtime integrity boundary
```

The command creates a directory under the home directory, runs the attacks,
prints the result, and deletes the directory. Exit 0 means `verified` is true.

The protected file starts as audit enabled, mode `strict`, destination
`https://alerts.example/hook`. After every contained attempt it is the same
text. The same concatenation without the profile changes a separate control
file to `disabled`.

Attacks that must return `BLOCKED_BY_BOUNDARY`: direct write, shell
concatenation, isolated `python3 -I` open, ctypes, `os.execv`, `os.spawnv`,
a child Python, a compiled C writer, `os.replace`, a symlink, watchdog
`kill`, watchdog config, policy downgrade, audit disable, notification
redirect, secret read, a write with no control plane, a TCP port that is not
the gateway, the multi-step read/stage/replace, environment expansion,
command substitution, a shell function, an indirect script, a relative path,
and base64 `exec`.

`mcp_remote_files` is `NOT_ENFORCEABLE`. `stale_attestation` is
`DETECTED_ONLY`. A crash or an unrelated error is `TEST_FAILED` and clears
`verified`.

## Linux reference

On a disposable host:

```bash
sudo deploy/monitoring-integrity/linux/setup-boundary.sh --apply
```

Then install `varden-agent.service` and `varden-watchdog.service`.
`Restart=no` is set so a failed watchdog does not come back in a weaker unit.
The development script exits 2 unless it is root and `--apply` is present.

## Predictive Authority

`analyse(registry)` labels an interruption `INTERCEPTED` /
`python_interceptor`. Passing a probe claim with `origin="probe"` and
`verified=True` labels covered surfaces with that claim's tier and mechanism.
A remote MCP edge stays `NOT_ENFORCEABLE`. The hot-path decider does not run
the graph and does not launch `sandbox-exec`.

## Supervised launch

`varden run` is the execution entry. `varden runtime integrity` inspects; it does not start the agent.

```bash
varden run --protected --workspace ./work --protected-path /var/lib/varden/monitoring.json -- python agent.py
```

`--protected` probes the Seatbelt profile and does not start the command if the probe can modify the file. There is no silent unsandboxed fallback. `--observe` is the explicit weaker launch and is not described as OS enforcement. Omitting both flags refuses to launch.

The supervisor writes the HMAC key outside the agent's read allowlist. A record is `VERIFIED` only while that process identity is still alive, the MAC checks, and the record is inside its freshness window. After exit the state is `TERMINATED`. A gauntlet result is not the live posture of another process.

Seatbelt remains an experimental, host-probed mechanism. Named `sandbox-exec -n` profiles are not used; on macOS 27.2 `sandbox-exec -n no-network` was killed (exit 137). App Sandbox and an XPC helper are not substitutes for arbitrary CLI agents: App Sandbox needs a signed bundle, and an XPC helper that accepted agent commands would be a privileged shell. Neither is implemented.

Linux user separation and the bubblewrap adapter are not executed on this host. Docker is not running and Colima is not running. Windows restricted-token code is present and refuses to launch on macOS. Neither platform is verified. The assurance matrix in `varden run --capabilities` has no `verified` cell. Same-user processes outside the launched macOS tree can still read the supervisor state directory; supervisor isolation is scoped to that tree.

`.github/workflows/mip-linux-boundary.yml`, `mip-macos-boundary.yml`, and `mip-windows-boundary.yml` are the native jobs. A workflow file is not a test result. Until each job has a recorded success, that platform stays unverified.

Attestation expiry under `continue_restricted` drops `VERIFIED` and leaves the process running, because Seatbelt is already applied by the kernel. `terminate` is an explicit supervisor action and reports `termination_confirmed` only after the process identity is gone. Renewal re-seals `issued_at` for the same process identity when the protected bytes still match. The agent does not hold the key.

## What this still does not prevent

- An unsandboxed macOS process of the same user.
- A process started before the profile, or one that escaped the launcher.
- Files on a remote MCP server.
- A Linux uid boundary, until that reference is executed and probed on Linux.
- Seatbelt syntax on a different Darwin build than the one probed here.
- Replacing the supervisor itself, if the agent is the supervisor.
