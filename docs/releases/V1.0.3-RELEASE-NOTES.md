# Varden v1.0.3 release notes (draft)

Do not publish until the release gate is accepted. This text is the GitHub release body for tag `v1.0.3`. It is not the v1.0.2 release.

## Overview

1.0.3 is a security patch on the published 1.0.2 tag. It stops the SDK and the MCP gateway from running a tool after the control plane has already returned a deny, when that deny was not an HTTP 403 with `decision.action` of exactly `block` or `require_approval`.

1.0.2 remains the release that fixed Predictive Authority client-config override, tenant scoping, demo isolation, session-eviction continuity, and the locked runtime contract (commit `5924532`). Those fixes are already in 1.0.2. 1.0.3 does not replace them and does not add features.

## Security fix

Affected versions: `v1.0.0`, `v1.0.1`, `v1.0.2`.

Reproduced on those tags with a side-effect counter:

- `guarded` + `fail_mode=closed` + HTTP 200 `decision.action=approval_required`: the tool ran.
- `guarded` + `fail_mode=open` + HTTP 503 whose `detail.decision.action` is `require_approval`: the tool ran.

The stock `/sdk/guard` handler returns HTTP 403 for `block`, `require_approval`, and `approval_required`. It returns the 503 shape when the approval record cannot be persisted. Default `fail_mode` for `guarded` and `strict` is `closed`. `strict` rejects `fail_mode=open`. The 503 bypass needs the explicit `guarded` + `fail_mode=open` configuration plus that persistence failure. The HTTP 200 alias bypass was shown against the SDK. The current server does not emit that 200 shape.

1.0.3 treats a response as a deny when:

- the HTTP status is 403, or
- `decision.action` or `decision.effective_action` is `block`, `blocked`, `require_approval`, or `approval_required`.

The decision object is the top-level `decision` field, or the same field inside one FastAPI `detail` wrapper. If those two fields disagree, a deny wins. A decision slot that exists but is not a recognized policy action is not an allow. JSON on the action (`args`, `metadata`, nested `decision` or `detail`) is not consulted. The MCP gateway uses the same rule and does not forward a denied `tools/call`.

## What did not change

- `observe` records a block and still runs the protected call.
- `fail_mode=open` still runs the protected call when the control plane returns no decision: disconnect, timeout, unexpected exception, or a body with no decision slot.
- `allow`, `warn`, `monitor`, and `sanitise` still execute.
- Locked runtime mode and fail mode are unchanged. A local `fail_mode=open` still cannot open a locked closed contract.
- Predictive Authority topology rules are unchanged. Multi-worker detection is still not multi-worker correctness.

## Upgrade

Upgrade from 1.0.2 if you set `fail_mode=open` on `guarded`, or if anything in front of `/sdk/guard` can change a 403 into another status. No policy migration. Keep `VARDEN_PA_DEPLOYMENT=single_worker` for Predictive Authority enforce mode, as in 1.0.2.
