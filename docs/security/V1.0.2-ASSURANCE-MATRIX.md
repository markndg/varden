Date: 2026-10-09. Branch: `fix/v1.0.2-security-assurance`.

This maps external review comments to the code and tests. It does not treat a green suite as proof of a property the assertions do not check.

Both were reproduced on the `v1.0.2` tag with a side-effect counter greater than zero. | `docs/security/V1.0.2-ENFORCEMENT-ASSESSMENT.md`. `tests/security/test_guard_response_enforcement.py`. | Multi-worker detection could be mistaken for multi-worker correctness. | `pa_deployment_status` fail-safes enforce mode when worker env is greater than 1 or the deployment is undeclared, unless the operator sets `multi_worker_allowed` / `VARDEN_PA_ALLOW_MULTI_WORKER`. A single process that declares `single_worker` while a sibling uses another database still misses that sibling's chain. ## Gauntlet claims vs assertions

| Finding | What the tests show | What they do not show |
|---|---|---|
| G-SDK-MODE-01 | After lock, a weaker `protect`, ContextVar swap, or attribute poison still raises `VardenBlockedError` for a control-plane deny the test server returns as HTTP 403. | They do not prove every HTTP body shape. G-SDK-RESP-01 is the gap those tests did not catch. |
| G-SDK-RESP-01 | On this branch, the cases in `test_guard_response_enforcement.py` leave the side-effect list empty when they raise. | They stub the HTTP client. They do not run a live approval-store failure inside `create_app`. The stock 503 shape is covered as a body, not as a disk-full integration. |
| G-PA-MULTI-01 | Undeclared and detected multi-worker enforce paths fail safe. A split chain across two declared single-worker processes is still an allow on the process that never saw the earlier hop, unless leases on one shared database observe both workers. | They do not show a correct merged authority graph across processes. |
| G-PA-EVICT-01 / 02 | Eviction and tombstone exhaustion fail safe rather than returning a fresh allow for accumulated sessions. | They do not restore the evicted graph. |
| G-PA-RESTART-01 | With ContinuityStore, reintroduction of a prior-authority key fails safe. | `cross_restart_continuity_verified` stays false. Unbound engines do not have the durable marker. |
| G-FS-01 | Intercepted filesystem APIs get a pre-execution decision for classified sensitive targets. | Not race-free. Status stays `PARTIAL`. |
| G-COV-ATTEST-01 | A poisoned `mark(ENFORCED)` with a fake probe does not survive verification after the seal. | In-process code can still call a saved original. The honest outcome is loss of `ENFORCED`, not prevention of that call. |
